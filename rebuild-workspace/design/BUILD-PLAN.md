# monday Master Builder: build plan

Re-cut 2026-10-14 under A24 to A28: one surface, Claude Code, on the user's machine, Windows or Mac, with identical behaviour and every shipped script, hook and tool in Python; assumptions that may carry a proof of concept while staying visibly unconfirmed, with the user as the one who confirms and a sign-off that warns rather than blocks; no GitHub account needed, a local archive by default and a GitHub archive as an option; readiness opening with goals and pains, the call type a best guess, and the hour as the floor rather than the typical case; one yes for a proof of concept in the user's own account, and sample data built for realism. The stage-2 consistency check of the same day is applied. Archive simplified and development-only deletes allowed per the user's answers of 2026-10-14, and full headless suite on both systems per the user's answer of 2026-10-14. Emails as pasted text or screenshots, and the goal-quote grader check, per the user's answers of 2026-10-14. The 2026-10-13 revision folded A17 to A23: the AI offerings as element kinds in the main line, every feature the connector exposes in scope, build first with the sales and SOP layers deferred, one surface, the per-client build target with the workspace rule, client folders in two phases with a generic default home, and the build notes. Earlier revisions folded A1 to A16 and the fixture work of stage 1. Written against `ARCHITECTURE.md` as re-cut in the same stage-2 task (cited as A§n) and `AMENDMENTS.md` (cited as A1 to A28). Every package, template, skill, reference, script, agent, hook, test and release check here carries a tier: `v1-core`, `v2` or `v2-or-v3`; a package that holds more than one tier is marked split and names in its acceptance what leaves the v1 acceptance and what it gains.

**Authority order.** `AMENDMENTS.md` wins over `ARCHITECTURE.md`, which wins over this file. Where the amendments changed something the architecture had already written down, this plan follows the amendment and records the difference in section 6, so nobody has to guess which text is current. Where the fixture review reversed a rule an earlier version of this plan had written in, the old text is gone rather than scoped beside the new, and section 4 carries a test that would catch the old behaviour coming back.

Section 0 holds the three decisions that are still open and the four questions that ship with a default. Section 1 is the stage order, section 2 the work packages, section 3 the file ownership map, section 4 the test plan, section 5 the release checks, section 6 the conflicts resolved here.
