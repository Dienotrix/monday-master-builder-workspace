## 2. How WP2 and WP3 were run, and the shape WP4 keeps

WP2 and WP3 ran as one chain, one agent at a time: a contract that turns each acceptance sentence into numbered clauses with source, acceptance moment and test, copying the shapes and listing the gaps, deciding nothing; a decisions file that settles each gap with a decision, a reason naming the source that wins and a follow-up; the record-map edits; the fixture with its notes and, in WP3, an independent trace check of it; the code in two parts with an API note; one adversarial review of the risky part, each finding proved by a throwaway probe outside the repository; the fixes, logged back into the decisions file; a checklist that ticks every clause against a named test; then the kept run on each system. Sonnet wrote the contract, the record-map edits, the trace check and the checklist; the session model wrote the decisions, the fixture, the code, the review and the fixes.

WP4 keeps that order and those tiers, with three changes: the fixture is the trap fixture of A§9.6 (planted text, its clean twin, payload samples and two planted client records) rather than recorded reads; it is built and checked on macOS first, on this Mac, and then on Windows; and the review goes at bypasses, because a miss in the lint reaches a client's account and a clean twin only measures the cases someone thought of.
