## The frame

- Launch: `[interpreter, <plugin>/scripts/ledger.py, (--record <client folder>), <command> [action] flags...]`. `--record` is global and comes first; the current folder is the default. A folder without `CLIENT.md` or `account.json` is exit 3 naming the missing file.
- `main()` holds `mc.record_mutex(root)` once around the command and its `emit` (W25: the hold lasts until the command has printed). Every lease primitive the commands call re-enters it (W26, proved by the first test).
- Envelope: `{"ok": code != 1, "command": "<name as typed>", "asked_by": <--strand or null>, **payload}`; `refusals` on exit 1 (`mc.Refusal`), `error` on exit 3 (`mc.CannotRun`), plus a top-level `committed` when the exception carries one. A usage error is exit 3 with file `ledger.py`, field `arguments`. Any other exception is exit 3 with the envelope.
- `COMMANDS` maps the 22 forms to `cmd_x(root, args) -> (code, payload)`. `run` is a group (`start`, `heartbeat`, `end`); `live-map` takes an optional positional `set`. A command left `None` skips the unknown-argument check, so part 2 must add its flags in `build_parser()` and replace `None`.
- Adding a part-2 command: write `cmd_x`, put it in `COMMANDS`, add its flags in `build_parser()` (`groups[name].add_argument`; `--strand` is already there for `classify`, `native-map`, `estimate`, `compare`, `snapshot`, `reconcile`). Inside, start with `led = Ledger(root, short)` and `refuse(*led.newer())`, collect every refusal, `refuse(*reasons)`, then write through `commit()`.

- **Fence and run (W28, W29)**: `fenced(root, args, states)` is the common opening of a fenced strand command: newer schemas, the three fence flags (missing ones are refusals, never read from the lock), `--expect-sha`, the holder strand (`mc.lease_status`), and the presented run. `fence(root, args)` calls `mc.lease_fence`: `(False, reason)` is exit 1, an exception (mutex timeout, torn lock) propagates as exit 3. After the fence, call `led.reload()`: the passing fence rewrote `account.json`'s lease mirror.
- **Writing (W25, W33, W34)**: `commit(command, steps, run_id, next_call)` runs `[(record-relative name, callable, lease mark), ...]` in order. A failure of the first is exit 3 naming its file with nothing committed; a later one is exit 3 with error field `committed` and the `committed` object `{command, written, not_written, lease, run_id, next}`. `json_step(root, path, data)` writes JSON through `mc.write_file` (backup, then in place). `save_build(led, command)` stamps `updated_at` and writes one `build.json`, returning `{name: new sha}`. `sha_reason(led, expect)` is W34's check (`none` = must not exist). `map_step(led)` renders `live/live-map.md` from `live_objects` and returns `None` when the rows are unchanged; `map_rows(text)` and `map_view(row)` read and compare the map (nine or ten columns).
- **Logs (W21)**: `entry_log(strand, type, version, key, lines)` builds the `log` entries a command prints; ledger.py never writes `log.md`.
- **Check (W63)**: `Checker(root, only).run()` gives `blocking`, `warnings` and `shas`. Part 2 can extend it, for example by checking the `reconcile` findings or the `native_map` shape, with `self.block(...)` and `self.warn(...)`.

## Choices taken where the decisions are silent (worth the user's nod)

1. **Referenced rows at approval.** The element-key table carries key, kind and name only, so `approval` takes `--referenced <key>` (repeatable) to plan a row as `pre-existing-referenced` (W12 needs approval to plan it).
2. **Other origins at intent.** `intent --origin pre-existing-modified|other-strand-modified` may change a planned `created` row's origin, only while it is planned; `pre-existing-referenced` never goes through `intent`.
3. **Two keys on `attempt`.** `attempt` carries `operation` and `retry` beside `run_id`, `started_at` and `intent_digest`: `record` needs to know that the call was an archive, and `retry` (true only for a retry out of `mismatch`) enforces "once" for the one different call form. `check` accepts the extra keys.
4. **`intent --product`** sets a workspace row's `product` (W11 names the field and no flag). It is required on a workspace create and refused on other rows.
5. **`irreversible-yes --approval-ref`** (optional, default the row's ref): an archive or a change of a row kept from an earlier revision is approved by the later revision, whose `irreversible_listed` names it.
6. **Missing `--expect-sha`** is a refusal (exit 1), like the fence flags (W29), not a usage error.
7. **String ids for column, AI column and group rows.** monday gives these string keys, so `record --id` accepts `[A-Za-z0-9_]+` for them; every other `--id` must be digits (W35).
8. **An item batch's `approval_ref`** is the approval of the strand's current version, else its board's.
9. **Moves the table leaves to the operation:** `archive` only from `verified` (with an id or item ids); `connect` and `convert` from `planned` or `verified`; `update` from `verified` or `written`; an `update` is classed as its type's create.
10. **Row normalisation.** A row a command changes is rewritten with every `build/2` field in record-map order (the optional ones at their defaults); rows the command does not touch stay as found.
11. **`bind`** reads the data object itself (no `data` wrapper); `name` falls back to the slug and `tier` to `unknown`; a refresh prints no log entry; `kind` and `build_target` are copied from `CLIENT.md` at every bind.
12. **`workspaces`** refuses re-recording the same id for the same product ("nothing to record").
13. **The holder strand.** Every fenced command, and `run start`, refuses when the lease is held by a strand other than `--strand` (W92's "the fence checks that strand's lease"), before the fence runs.
14. **`run start --kind`** (default `build`; `doc-copy` refused as deferred), and `--answer-words` required with a yes.
15. **Archive evidence at the yes.** `irreversible-yes` refuses a `--what` that mentions archiving without `--evidence`; the hard check is at `intent`, which refuses an archive whose yes (or, under `own-account-poc`, whose `--evidence`) has none (K215).
16. **`check` and card entries.** A `card` entry counts as listed when its key is a row of the ledger; `per-item` and `grouped` entries must be in an approval's lists. An account-level row without a scope blocks only once it is past `planned`. A record with live objects and no `live/live-map.md` blocks.
17. **Publication and activation of an account-level parent** take the parent's scope; a publication's name must say `active` or `inactive` (K160's decided state).
18. **Digests of the kinds W73 does not list** (form, widget, AI column, sequence, webhook) cover the whole read object.
19. **An other-strand-modified row at `run end`** refreshes the owner's live row (`monday_id`, `kind`, `workspace`, `state`, `digest`, `last_verified`) and keeps its `dependants`.
20. **State from a read.** `verify` sets `state` from the read's `state` when it is a state token (`ACTIVE` lowered), else `active` on a first match.
21. **`do-not-change` beyond other-strand rows.** `intent` refuses any write whose own live row or whose parent's live row is `do-not-change` (K157's third case, generalised).
22. **The `build/2` skeleton** a first approval creates is embedded in `ledger.py`, not read from the template.
23. **The element table's header** must begin `key | kind | name`; any other header is a problem, as is a heading with no table.
24. **The live-map header is ten columns** (W59), where K218's text still lists nine.

## Choices taken where the decisions are silent (worth the user's nod)

1. **Signals and attributes follow the reads' README** (its signal-token table and its N12 attribute rules, the reads author's choices 1 to 9): signals are facts, present whenever their condition holds, and compared as a set; only the imitation and relation-target tokens are confined to N7 and N8, and `N11` to the boards handed back.
2. **The lineage cap.** Up to five hops are walked; when a sixth readable board would be needed the walk ends `UNRESOLVED`, note "longer than 5 hops", with six ids in the chain and `hops` 5. A chain that reaches a readable board with a null pointer is `NO_LINEAGE`, that hop counted. A hop id that no page returns and no page lists as missing gives `result: null`, note "waiting on the read of <id>", and the class `pending`.
3. **The page diff is recomputed.** On a `boards_ids` page `ledger.py` diffs requested against returned itself; when the file's own `missing_ids` disagree, a note says so and the computed diff is used.
4. **Template names to entities.** Family E (named in NO 4's opening, unread) is in the catalogue as family `E`. NO 3.1's `project_companion` and `project` read as the entity `companion`, `project_companion_subitems` as subitems with an unknown parent, Service `subitems` (families D and E) as `tickets_subitems`, `contacts` as `service_contacts`, and `portal_custom_object` as `portal`. A lineage to a CRM companion template gives `native_crm_companion_board` under N2; a lineage to a Start here doc on a board that is not a document names no entity.
5. **Families.** CRM: the types first, then the lineage's catalogue row (W84), never a template view; the Quotes & Invoices views sit with CRM core v1, the row their template sits in. Service: the lineage's family, then the template view's, then the Tickets extended-id fallback.
6. **N5.** A lineage counts for N5 only when it names a subitems template; the parent entity comes from R2's parent first, then the lineage, then the signature, else `unknown`; the install kind is the lineage's (`direct_install`, `descendant_copy(n)`, `lineage_unresolved`, or null). N1a and N1b take theirs the same way, a Portal template view alone giving `direct_install`.
7. **N8's "zero reserved ids"** counts the unsuffixed, non-default ids of every signature that has a threshold; the default-shaped ids of Incidents, CSAT Survey and Service Contacts do not count. **L3** needs at least one column read, since a deleted board's empty column list proves nothing.
8. **Projects.** A portfolio with no `portfolio_items` page counts as an incomplete read, as a cursor does. `C3` is listed on a connected result only and `C4` on an unconnected one only. `native_map.portfolio.<X>.projects[]` lists the projects connected or partial with X; `overview_board_id`, `overview_state` and `planner_board_id` are null there, and `folder_id` is the tasks board's folder.
9. **`needs_review`** lists every `native_` result below high confidence, with "protect as native and ask", on every `classify` and `native-map` call.
10. **The map's keys.** `native_map` uses W16's names for the N5 entries (`qi_line_items`, `deals_subitems`, `lifecycle_subitems`, `tickets_subitems`), keeps N6 under `crm.companion`, N7 under `service.satellite_probable` and N10 under its fingerprint's entity. `native_board_ids_by_entity` and `reserved_column_ids` are keyed `"<product>/<entity>"`, as A§7.3's example is. `template_source_ids` and `template_view_ids` hold the catalogue of every product the account carries (core giving NO 7.2's role templates) and every id the reads met. `product_workspaces` takes the read's kinds, except that a client workspace already recorded keeps its entry. A confirmation is kept only while the board and the rule are unchanged and the entry is still high.
11. **The snapshot scope.** Every strand row with an id is in scope by that id (so the strand's automations, forms, docs, dashboards, agents, workflows and Vibe apps are); `scope.boards` is the strand's board-kind rows and the protected board-kind live rows; automations and forms are also kept when their board is in scope. The inventory keeps the boards of the client's workspaces and lists any other as dropped. A protected row of a kind the read covers whose object the read lacks gets `digest_at_snapshot: null` and `moved: true`.
12. **Compare's field names.** A board appearing or disappearing in the inventory is `board:<id>`, an object of another part `<kind>:<id>.read`; the two hashes are `ledger:<short>.ledger_sha256` and `account:record.account_sha256`. A changed-outside warning names the before snapshot and `<key>.digest`. A refused document is blocking against the appendix file, and so is an `--appendix` whose file has no such section.
13. **The tokenizer's edges.** An unclosed fence and a `json` block that does not parse are refused as documents the scan cannot read; JSON `query` strings are found at any depth. The reasons: a syntax error or a type-system definition as met, else `mutation`, then `subscription`, then "more than one operation", then "no operation"; a pass is "one query".
14. **Reconcile's edges.** Claims share one id namespace across kinds. A live object counted as a row's match is never also an extra; a doc container board and a workflow's backing board are never extras on their own; an automation is an extra by its board's workspace. Publication and activation rows are reconciled by their parent's live flag (a sequence's activation is not in the inventory). A verified Vibe app whose live status is not `READY` is `partial` before its digest is compared. Duplicates carry a `proposals` list beside the elements, so the element shape stays as pinned. Notes are built from what the row itself records, else they name the two digests. The order: automations, agents, Vibe apps, workflows, then the other kinds by their first key in natural order, kinds holding only extras last.
15. **Classify-only.** A heartbeat that does not parse (`fresh: null`) is read as not fresh; the envelope's `asked_by` is `--asked-by` when it is given.
16. **Estimate's edges.** A sibling's `item_batch` rows count one call each, since its item counts are its own session's inputs; this strand's seed items come from `--inputs` only. Account checks are `1 + ceil(writes low / 20)` even with no open rows. The output adds `batches` (`create_items`, `update_items`). Input keys naming credits, prices or packages are listed by name under `fields_present_not_read` and never read.
17. **The frame.** `snapshot`, `reconcile` and `estimate` need `--strand` (a usage error without it), `--asked-by` takes a three-digit short id, and the unknown-argument check now covers every command.

## Choices taken where the decisions are silent (worth the user's nod)

5. **R12's edges.** A kept `planned` row whose kind changed is re-planned as a new row of the new kind (nothing of it was built); its origin follows the new `--referenced`. The "latest approval" a create needs is the highest revision approved for the strand's current version.

7. **R1's exception** for an `--approval-ref` of another version is an `update` or `archive` of a row that exists; the mode is the current version's either way.
8. **R18 and R20** take the refusal readings: `change-check` refused while another strand holds the lease (rather than a block per strand), and `approval` refused while this strand's lease carries a run.
