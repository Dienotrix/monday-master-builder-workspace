## 2. How WP2 was run, and the shape WP3 keeps

WP2 ran as one chain, one agent at a time: a contract that turns each acceptance sentence into numbered clauses with source, acceptance moment and test, copies the shapes and lists the gaps, deciding nothing; a decisions file that settles each gap with a decision, a reason naming the source that wins and a follow-up (a record-map edit, a design touch-up, or none); the record-map edits; a hand-built fixture with its notes; the code in two parts with an API note between them; one adversarial review of the risky part (the lease), each finding proved by a throwaway probe outside the repository; the fixes, logged back into the decisions file; a checklist that ticks every clause against a named test and lists what is not met plainly; then the Windows run, with its results kept. Sonnet wrote the contract, the record-map edits, the checklist and the small fixes; the session model wrote the decisions, the fixture, the code, the review and the fixes.

WP3 keeps that order and those tiers, with three changes: the fixtures are synthetic reads under A29 rather than a hand-built record tree; the cross-system check runs the other way round, built and checked on Windows here and then on macOS; and two steps may run side by side (the reads and the first code part write different files).
