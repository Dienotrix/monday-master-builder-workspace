## How to read the table

- A test is named exactly as it is in the file, with `[L]`, `[R]` or `[S]` for the file. I opened every test I cite. A row's evidence says what the test asserts; where a test only runs a command, or covers a smaller set than the clause's Test line names, the row says so, and the row is `not met` if the gap is material.
- `met (test)`: a named test asserts the clause's point as its Test line, amended by any decision, asks. `met (inspection)`: an inspection clause, met at a named place. `met against synthetic reads`: a classify, compare, reconcile, native-map or reads clause met by a named test against `tests/fixtures/snapshots/`; it always also owes the capture (A11-1) of amendment A29, which the row says. `stage 4 headless`: needs WP14's runner and the seed records. `Windows run` and `macOS run`: need the kept run on that system; the Windows run is being made in step 10 and the main session updates those rows; the macOS run is the user's, later. `changed by decision`: a decision changed the clause; the row names it and says by which test the changed form is met. `not met`: the row says which part and whether the behaviour exists.
- A row can end with `Still owed:`, the later moments its contract Accept line names (the Windows run, the macOS run, a headless row, the capture). They do not change the status; the summary lists them.
- A probe I made in a throwaway test in the scratch folder, outside the repository, is called a probe and is never counted as a test.
