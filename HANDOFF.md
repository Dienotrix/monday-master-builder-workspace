## 5. Cost policy (decided 2026-09-20, because usage was getting out of control)
- **Ultracode off** as the standing mode. Workflows only where fan-out pays: independent packages in parallel, or adversarial verification of a high-risk artifact. Sequential work runs single-agent or inline.
- **Tier by job.** Mechanical writing (fixtures from a spec, templates, tests, docs, scans): `model: 'sonnet'`, `effort: 'low'` or `'medium'`. Judgment (design re-cuts, the fix pass, review of ledger/lease/guard/intake/blueprint/build skills): the session model at `'high'`. Grep-style checks (coverage, lint sweeps): `'haiku'`.
- **Let the mechanical gates be the verification.** Unit tests, `lint_plugin.py`, `agnostic_sweep.py` (from stage 2), `record.py check`, headless runs and the answer keys already prove most things; do not also send an adversarial reviewer at outputs a test proves. Review one artifact per package at most, and only the risky one.
- **Small runs.** At most ~8 agents per workflow so a spend-limit kill loses little; every agent writes its result to a file as it goes; keep the returned schema tiny (paths + a headline); never a large structured return.
- **Lean main session.** Do not paste big files into chat; let agents read them. Start a new session at each stage boundary from this file.
- `resumeFromRunId` is same-session only: a run interrupted by the limit must be resumed in the session that started it. Plan runs so they finish inside one usage window.

## 6. What the earlier session learned about running workflows
Small return schemas with detail in files (a large schema failed five times); one file per agent to avoid write collisions; sequential passes when two agents must edit one file; incremental saves; verifiers re-count and spot-check quotes — they caught real errors every round; a plan/ownership map before a multi-file edit; the fix pass reads the checks' files, not just the summaries. The earlier run scripts are not kept; author new ones from the workflow-authoring reference with these lessons. The stage 1b run (2026-10-13) confirmed the shape: three editors in parallel on their own files, each from a line-anchored map written first by a cheap reader, then a refresher, a checker and a fixer; six agents, no errors, and the checker still found 36 real inconsistencies, so the check-and-fix pair stays in every run.
